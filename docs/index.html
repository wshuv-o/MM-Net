Abstract

Sleep-disordered breathing is common in the weeks after an ischemic stroke and predicts worse recovery, yet automatic sleep analysis reads only the electroencephalogram and reports only sleep stages. A clinical polysomnogram records far more, and in this population the disease is plainly visible in those cardiorespiratory channels: the median patient here has a scored respiratory event in 13% of epochs.

We present MM-Net, a two-stream multi-task model that reads fourteen neural and cardiorespiratory channels and produces two outputs from one forward pass: the sleep stage of every 30-second epoch, and a per-epoch respiratory-event label. A direct cardiorespiratory path carries breathing effort to the respiratory decision, bypassing the staging objective. On iSLEEPS (99 patients, 92,560 epochs) under patient-independent ten-fold cross-validation, MM-Net stages sleep at 0.739 accuracy (κ 0.634) and detects respiratory events at 0.782 AUC with 2.76 M trainable parameters.

We benchmark thirteen deep architectures retrained on this cohort and three applied zero-shot from healthy sleep. Every retrained baseline lands between 0.613 and 0.720 accuracy, and six are reimplemented here, each recovering its published accuracy to within 0.04, which places the limit in the cohort itself.

The honest headline is not the staging number. Neural-only scores 0.741 and the full model 0.739: the cardiorespiratory stream does not improve staging. What it adds is a second clinical output, on a cohort where every architecture we tried sits near the same ceiling.

Each stream serves its own physiology

Removing one modality and retraining, nine times over. The pattern is a double dissociation: deleting the neural stream costs staging and leaves breathing intact; deleting the cardiorespiratory stream does the reverse. p is Wilcoxon on ten fold-means, Holm-corrected within each metric.

Run the model in your browser

The released checkpoint, executing here, on a patient it never saw during training. Nothing is fetched from a server once the files load: the weights run on your machine and the hypnogram is computed while you watch, then checked against what PyTorch produced for the same patient.

What runs and what does not. Your browser runs MM-Net itself, all 2.76 M parameters. It does not run the feature extraction or the frozen LaBraM encoder that produce the 388-dimensional neural vector, because LaBraM is far too large to ship to a browser. The inputs are pre-extracted. So this shows the published weights reproducing the published result, not the whole pipeline running client-side.

Checkpoints

Per-fold weights for the reported configuration, seed 42. Each file carries its own config, the test-subject list for that fold, the scores it achieved, and the parameter count, so a checkpoint can be matched to the row it produced without trusting the filename.

Loading one. torch.load(path, weights_only=False) gives a dict with state_dict, config, fold, test_subjects and scores. Build the network with MMFeatureNet(**config) from model/mmnet_core.py, swap card_enc for CardioCNN, then load. A checkpoint reproduces its fold to within GPU non-determinism, which is why each stores the scores it actually achieved.
