Reading the whole sleeping body

A two-stream multi-task model that stages sleep and detects respiratory events from one pass over a stroke patient’s polysomnogram. Trained and evaluated on iSLEEPS: 99 patients, 92,560 epochs, patient-independent ten-fold cross-validation.

Download checkpoints Code on GitHub iSLEEPS corpus

What the model is for

Automatic sleep analysis reads the electroencephalogram and reports sleep stages. A clinical polysomnogram records far more, and after a stroke those cardiorespiratory channels carry the sleep-disordered breathing that predicts recovery: the median patient here has a scored respiratory event in 13% of epochs.

MM-Net reads fourteen neural and cardiorespiratory channels and produces two clinical outputs from a single forward pass, with a direct cardiorespiratory path carrying breathing effort to the respiratory decision so the staging objective cannot squeeze it out.

The honest headline is not the staging number. Neural-only scores 0.741 and the full model 0.739: adding the cardiorespiratory stream does not improve staging. What it adds is a second clinical output at 0.782 AUC, for free, on a cohort where every architecture we tried sits near the same ceiling.

Each stream serves its own physiology

Removing one modality and retraining, nine times over. The pattern is a double dissociation: deleting the neural stream costs staging and leaves breathing intact; deleting the cardiorespiratory stream does the reverse. p is Wilcoxon on ten fold-means, Holm-corrected within each metric.

Checkpoints

Per-fold weights for the reported configuration, seed 42. Each file carries its own config, the test-subject list for that fold, the scores it achieved, and the parameter count, so a checkpoint can be matched to the row it produced without trusting the filename.

Loading one. torch.load(path, weights_only=False) gives a dict with state_dict, config, fold, test_subjects and scores. Build the network with MMFeatureNet(**config) from model/mmnet_core.py, swap card_enc for CardioCNN, then load. A checkpoint reproduces its fold to within GPU non-determinism, which is why each stores the scores it actually achieved.
